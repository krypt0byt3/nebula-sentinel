# nebula-gossip — Protocol & Crate Manual

**Crate:** `nebula-gossip` v0.1.0 (edition 2021) · `license = "Proprietary"`
**Location:** `/nebulasentinel/nebula-gossip`
**Wire spec of record:** `/nebulasentinel/GOSSIP_ENVELOPE_SPEC.md` (Draft v1)
**Schema string:** `gossip/1` (constant `SCHEMA`, `src/lib.rs:45`)

This document describes the **current state** of the source, not the aspirational
spec. Where the implemented behavior differs from `GOSSIP_ENVELOPE_SPEC.md`, the
code wins and the divergence is called out explicitly.

---

## 1. Purpose

`nebula-gossip` is the **single shared crate** that defines the GOSSIP wire
format for the entire NebulaSentinel ecosystem. The design goal is *one
envelope, many transports*: agents, Cortex, Dopamine, Nexus, Red Nebula, and
Synapse all emit and consume byte-identical [`Envelope`] values regardless of
whether a message travels over agent↔agent UDP gossip, the Nexus HTTPS poll
cycle, or Synapse's cross-customer channel.

Every ecosystem component pulls this crate in as a **path dependency**
(`nebula-gossip = { path = "../nebula-gossip" }`, per `Cargo.toml`), so they all
compile against exactly the same struct definitions and serialization — this is
what guarantees the messages are structurally identical on the wire.

The crate provides four things:

1. `Envelope` — the universal message wrapper (identity, provenance, trust, payload).
2. `MsgType` + typed payloads (`payload::IocPayload`, `payload::AtcPayload`).
3. Deterministic `dedup_key` derivation for collapsing duplicates.
4. ed25519 signing/verification of both envelopes and individual relay hops
   (feature `signing`, **on by default**).

## 3. The envelope (JSON wire format)

`Envelope` (`src/lib.rs:168-195`) serializes to JSON via serde with field names
as written (no rename). Field groups:

### Identity
| Field | Type | Notes |
|---|---|---|
| `schema` | `String` | Always `"gossip/1"` from the builder. |
| `msg_id` | `String` | Unique, roughly time-sortable. See §3.1. |
| `msg_type` | `MsgType` | Dotted string on the wire, e.g. `"atc.alert"` (§4). |
| `dedup_key` | `String` | Stable collapse key (§6). |

### Provenance
| Field | Type | Notes |
|---|---|---|
| `origin` | `Origin` | Who originated the message. |
| `relays` | `Vec<Relay>` | `#[serde(default)]` — omitted/empty when direct; one record appended per forwarding hop. |
| `corroboration` | `Corroboration` | Independent-source count + first/last seen (§7). |

### Trust
| Field | Type | Notes |
|---|---|---|
| `confidence` | `u8` | 0–100 (builder clamps to ≤100). |
| `severity` | `Severity` | `#[serde(default)]` → `info`. Serialized snake_case. |
| `ttl_secs` | `u64` | Expiry window; see `is_expired` (§8). |
| `sig` | `Option<Signature>` | Origin ed25519 signature; `skip_serializing_if = None` (§5). |

### Timing / Payload
| Field | Type | Notes |
|---|---|---|
| `created_at` | `DateTime<Utc>` | RFC3339 on the wire. |
| `payload` | `serde_json::Value` | Free-form JSON; schema keyed to `msg_type` (§4). |

### 3.1 `msg_id` format

Generated by `new_msg_id()` (`src/lib.rs:316-319`) as
`"{:011x}-{uuid_v4}"` — an 11-hex-digit Unix-millis prefix followed by a random
UUIDv4, e.g. `0197f3a1b2c-1f0e...`. This gives rough time-ordering without a ULID
dependency.

> **Spec divergence:** `GOSSIP_ENVELOPE_SPEC.md` §2 shows `msg_id` as a ULID /
> UUIDv7. The implementation uses `millis_hex-UUIDv4` instead. Functionally
> equivalent (unique + time-prefixed) but not a literal ULID/UUIDv7.

### 3.2 `Origin` (`src/lib.rs:105-128`)

```jsonc
"origin": {
  "component": "nebula-agent",   // Component enum, kebab-case
  "id": "agent-7f3a",            // stable instance ID
  "tenant": "customer-acme",     // Option; omitted when None (isolation boundary)
  "site": "dc-east"              // Option; omitted when None
}
```
`tenant` is the hard isolation boundary. Constructors: `Origin::component(component, id)`
(single-tenant convenience), `.with_tenant(...)`, `.with_site(...)`.

### 3.3 `Component` (`src/lib.rs:63-101`)

Serialized kebab-case. Known variants: `NebulaAgent` (`nebula-agent`), `Cortex`
(`cortex`), `Dopamine` (`dopamine`), `Nexus` (`nexus`), `RedNebula`
(`red-nebula`), `Synapse` (`synapse`). Unknown names deserialize to
`Component::Other(String)` (via `#[serde(untagged)]`) and round-trip verbatim, so
a newer component never breaks an older parser. Helpers: `as_str()`, `parse(&str)`.

### 3.4 `Relay` (`src/lib.rs:132-139`)

```jsonc
{ "component": "nexus", "id": "nexus-01", "ts": "2026-...Z", "sig": "base64|null" }
```
Appended by each relayer. `sig` is an `Option<String>` (base64 ed25519 over the
relay-canonical bytes, §5.4); omitted when the hop is unsigned.

### 3.5 `Corroboration` (`src/lib.rs:144-155`)

```jsonc
{ "independent_sources": 3, "first_seen": "...", "last_seen": "..." }
```
`Corroboration::single(now)` initializes a fresh message with one source and
`first_seen == last_seen == now`. Higher `independent_sources` means more distinct
origins reported the same `dedup_key` → higher trust. The Nexus updates this as it
merges duplicates.

### 3.6 `Signature` (`src/lib.rs:158-163`)

```jsonc
{ "alg": "ed25519", "key_id": "agent-7f3a-2026", "value": "base64..." }
```
`key_id` names which key signed (rotation-friendly); `value` is base64 of the
64-byte ed25519 signature.

## 4. Message taxonomy — `MsgType` (`src/msgtype.rs`)

`MsgType` is a Rust enum serialized as its **dotted string** form via
`#[serde(from = "String", into = "String")]`. Unknown strings become
`MsgType::Other(String)` and round-trip verbatim (forward-compatible).

| Variant | Wire string | Meaning (per doc comments / spec) |
|---|---|---|
| `IocAlert` | `ioc.alert` | Shareable indicator (hash/IP/domain/etc.). |
| `IocFalsePositive` | `ioc.false_positive` | Retraction — IOC is benign, stop acting on it. |
| `AtcObservable` | `atc.observable` | Low-fidelity observation, not a threat. |
| `AtcAlert` | `atc.alert` | High-fidelity confirmed threat. |
| `AtcHealth` | `atc.health` | Liveness / operational status. |
| `ReputationScore` | `reputation.score` | Entity reputation update (IP/host/user risk). |
| `PeerSeen` | `peer.seen` | Peer sighting (topology / mesh membership). |
| `RuleProposal` | `rule.proposal` | Suggested detection rule for Nexus approval. |
| `IntelAdvisory` | `intel.advisory` | Curated/distributed intel (Nexus→fleet / cross-customer). |
| `SampleAvailable` | `sample.available` | A captured sample is available for pull. |
| `AssessmentFinding` | `assessment.finding` | Red Nebula assessment finding; can seed a retro hunt. |
| `Other(String)` | *(verbatim)* | Unknown/future type. |

> **Note:** `assessment.finding` exists in the code (`src/msgtype.rs:33,51,81`)
> but is **not** in the spec's §3 taxonomy table. Conversely the spec lists no
> extra types the code lacks.

Helpers (`src/msgtype.rs:38-66`):
- `as_str()` → dotted wire string.
- `domain()` → the `<domain>` prefix before the first `.` (e.g. `atc`, `ioc`) for routing/filtering.
- `is_atc()` → true for `AtcObservable | AtcAlert | AtcHealth`.

## 5. Signing (feature `signing`, `src/signing.rs`)

Pure-Rust ed25519 via `ed25519-dalek` v2 — identical behavior on agent and
Nexus with no C dependency. The module provides **two independent** signing
schemes: origin-envelope signing and per-relay-hop signing.

### 5.1 `Keypair` (`src/signing.rs:74-100`)

```rust
pub struct Keypair { pub signing: SigningKey, pub key_id: String }
```
| Method | `path:line` | Purpose |
|---|---|---|
| `Keypair::generate(key_id)` | `src/signing.rs:81` | Fresh keypair from `OsRng`. |
| `Keypair::from_secret_bytes(&[u8;32], key_id)` | `src/signing.rs:87` | Load from 32 raw secret-key bytes (persistence). |
| `public_bytes() -> [u8;32]` | `src/signing.rs:92` | Verifying-key bytes to distribute to receivers. |
| `public_b64() -> String` | `src/signing.rs:97` | Base64 of the public key for config/registries. |

`key_id` is stamped into `Signature.key_id` at sign time.

### 5.2 Canonical bytes — what gets signed (`src/signing.rs:40-71`)

The origin signs a dedicated `Canonical` struct, **not** the whole envelope. It
includes, in fixed field order: `schema`, `msg_id`, `msg_type` (as dotted
string), `dedup_key`, `origin`, `corroboration`, `confidence`, `severity`,
`ttl_secs`, `created_at` (RFC3339 string), `payload`.

It **deliberately excludes two fields**:
- **`sig`** — you can't sign the signature.
- **`relays`** — relay hops are appended *after* origin-signing, so including
  them would make every hop invalidate the origin signature.

Canonicalization is achieved by serializing this fixed-field-order struct with
`serde_json::to_vec` (serde preserves struct field order), making the signed
bytes independent of any JSON map ordering.

> Caveat: the "canonical" form relies on serde_json's struct field ordering and
> re-serialization of the nested `payload` `Value`; it is not a formal JCS
> canonicalization. Producer and verifier both go through `canonical_bytes`, so
> they agree, but interop with a non-Rust signer would require matching this
> exact serialization.

### 5.3 Envelope `sign` / `verify`

| Fn | `path:line` | Behavior |
|---|---|---|
| `sign(&mut Envelope, &Keypair) -> Result<(), SignError>` | `src/signing.rs:104` | Computes canonical bytes, signs, sets `env.sig = Signature { alg:"ed25519", key_id, value:base64 }`. |
| `verify(&Envelope, &[u8;32]) -> Result<(), SignError>` | `src/signing.rs:116` | Requires `env.sig` (else `NotSigned`), decodes base64 → 64-byte sig, rebuilds canonical bytes, verifies against the given public key. Errors: `BadKey`, `BadSignature`, `Verify`. |

Because relays are excluded, appending a relay hop after signing does **not**
break the origin signature (test `relays_do_not_break_origin_sig`,
`src/signing.rs:234`). Any tamper with a signed field does break it (test
`tampering_breaks_verification`, `src/signing.rs:224`).

### 5.4 Relay-hop signing

Separate scheme so each relayer can attest to *its own hop*, bound to the
message ID. Canonical relay bytes (`relay_canonical`, `src/signing.rs:133-136`)
are a pipe-delimited string, **not** JSON:

```
gossip-relay|<msg_id>|<component>|<relay.id>|<relay.ts RFC3339>
```

This binds the signature to the specific `msg_id` and hop metadata; the relay's
own `sig` field is excluded.

| Fn | `path:line` | Behavior |
|---|---|---|
| `sign_relay(msg_id, &mut Relay, &Keypair)` | `src/signing.rs:139` | Sets `relay.sig = Some(base64 sig)`. |
| `verify_relay(msg_id, &Relay, &[u8;32]) -> Result<(), SignError>` | `src/signing.rs:146` | Requires `relay.sig`, verifies pipe-delimited bytes against relayer's public key. |

Convenience on the envelope:
- `Envelope::add_relay(component, id, now)` (`src/lib.rs:213`) — appends an **unsigned** hop.
- `Envelope::add_relay_signed(component, id, now, &Keypair)` (`src/lib.rs:221`, `signing` only) — builds a `Relay` and signs it via `sign_relay` before pushing.

### 5.5 `SignError` (`src/signing.rs:19-38`)
`Serialize(serde_json::Error)`, `BadKey(String)`, `BadSignature(String)`,
`NotSigned`, `Verify`. Implements `Display` + `std::error::Error`.

### 5.6 base64
The crate ships its own minimal, dependency-free base64 encode/decode
(`src/signing.rs:156-199`) used for signature `value` and `public_b64()`.
Standard alphabet (`+/`), `=` padding on encode; decode ignores padding and
whitespace.

## 6. Dedup keys — idempotency (§6)

The `dedup_key` is the logical-identity key: two messages with the same
`dedup_key` are the *same fact* and get merged (corroboration bumped) rather than
duplicated. The `EnvelopeBuilder` auto-derives it:

- **IOC** (`payload_ioc`, `src/lib.rs:276`): `IocPayload::dedup_key()` →
  `ioc:<ioc_type>:<value>` (`src/payload.rs:91`). Same indicator from any source
  collapses.
- **ATC** (`payload_atc`, `src/lib.rs:283`): `AtcPayload::dedup_key(origin_id)`
  (`src/payload.rs:250`):
  - Health → `atc:health:<origin_id>` — one-per-origin, so the latest health
    replaces the prior.
  - Observable/Alert → `atc:<origin_id>:<category>:<entity>`, where `<entity>` is
    the entity's `path`, else `pid`, else `name`, else empty; `<category>`
    defaults to `event`. Distinct findings stay distinct; identical ones collapse.
- **Explicit override:** `EnvelopeBuilder::dedup_key(...)` (`src/lib.rs:270`)
  wins if set (the payload setters use `get_or_insert`, so an explicit key is
  preserved).
- **Fallback** (`build`, `src/lib.rs:291-294`): no key and non-typed payload →
  `<msg_type.as_str()>:<short_hash(payload_json)>`, so identical raw payloads
  still collapse. `short_hash` = first 8 bytes (16 hex chars) of SHA-256
  (`src/payload.rs:15`).

## 7. Payload families (`src/payload.rs`)

`payload` is free-form JSON keyed to `msg_type`; two families are fully typed.

### 7.1 `IocPayload` (`src/payload.rs:61-94`)

```jsonc
"payload": {
  "ioc_type": "sha256",   // md5|sha1|sha256|ipv4|ipv6|domain|url|file_path|
                          // process_name|registry_key|yara_rule|ja3|user_agent|email
  "value": "abcd...",
  "context":   { ... },   // IocContext, defaults if omitted
  "enforcement": { ... }  // Enforcement, defaults if omitted
}
```
- **`IocContext`** (`:45-57`, all optional/skip-if-empty): `malware_family`,
  `campaign`, `mitre_techniques: Vec<String>`, `description`, `kill_chain_phase`.
- **`Enforcement`** (`:28-42`): `recommended_action` (`observe|alert|block|quarantine`),
  `auto_enforce: bool`, `scope` (`same_host|same_tenant|ecosystem`). Default is
  `{ action:"alert", auto_enforce:false, scope:"same_tenant" }` — advisory, not
  mandatory; `auto_enforce:false` means a human/policy must approve before acting.
- Builders: `IocPayload::new(type, value)`, `.with_context(...)`, `.with_enforcement(...)`.

### 7.2 `AtcPayload` — three fidelity tiers (`src/payload.rs:150-262`)

One unified struct with a `tier` discriminator (`AtcTier`: `observable | alert |
health`, serialized snake_case). Fields irrelevant to a tier are
`skip_serializing_if`-omitted, so an observable stays lean while an alert carries
full detail. Constructors seed sensible defaults:

| Constructor | `path:line` | Sets |
|---|---|---|
| `AtcPayload::observable(category, observation)` | `:189` | tier=observable, disposition=`benign`. |
| `AtcPayload::alert(category, threat_name)` | `:207` | tier=alert, disposition=`malicious`. |
| `AtcPayload::health(status)` | `:225` | tier=health, `status` = healthy/degraded/unhealthy. |

Fields by area:
- **Observable + Alert:** `category`, `entity: AtcEntity`, `detector: AtcDetector`, `disposition` (`benign|unknown|suspicious|malicious`).
- **Observable only:** `observation` (human note).
- **Alert only:** `threat_name`, `mitre_techniques: Vec<String>`, `llm_analysis` (null if no LLM enrichment).
- **Health only:** `status`, `cognition: AtcCognition`, `collector_backend` (`ebpf|procmon`).

Sub-structs:
- **`AtcEntity`** (`:108-118`): `type` (serde-renamed from `entity_type`), `name`, `path`, `pid`. All optional.
- **`AtcDetector`** (`:122-134`): `engine`, `rule`, `source` (`"atc"` = LLM-enriched, `"legacy"` = raw detector output — first-class ATC-vs-Legacy distinction). Default engine `"unknown"`, source `"legacy"`.
- **`AtcCognition`** (`:138-145`): `llm_available: bool`, `llm_model`, `mode` (`"atc"|"legacy"`) — carried by health to catch a *silently degraded* agent.

Builders: `.with_entity(...)`, `.with_detector(...)`, `.with_cognition(...)`.

> **Spec vs code:** `GOSSIP_ENVELOPE_SPEC.md` §5 illustrates richer payloads
> (e.g. `evidence`, `mitre.{tactics,techniques}`, `iocs[]`, `suggested_action`,
> `uptime_secs`, `collector.{backend,events_per_min}`, `detection`, `queues`,
> `version`). The typed `AtcPayload` here implements a **subset**: `mitre_techniques`
> is a flat `Vec<String>`, `collector_backend` is a plain string, and there are
> no `evidence`/`iocs`/`suggested_action`/`uptime`/`detection`/`queues` fields.
> Because `payload` is ultimately a `serde_json::Value`, extra fields can still be
> carried via `payload_json`, but they are not part of the typed API.

## 8. Envelope construction & lifecycle

### 8.1 `EnvelopeBuilder` (`src/lib.rs:241-311`)

`Envelope::builder(msg_type, origin)` returns a builder with defaults:
`confidence=50`, `severity=Info`, `ttl_secs=86_400`, `payload=Null`,
`created_at=Utc::now()`. Chainable setters: `.confidence(c)` (clamped ≤100),
`.severity(s)`, `.ttl_secs(t)`, `.created_at(ts)`, `.dedup_key(k)`,
`.payload_json(v)`, `.payload_ioc(p)`, `.payload_atc(p)`. `.build()` fills
`schema`, a fresh `msg_id`, `corroboration = single(created_at)`, empty `relays`,
`sig = None`, and the derived `dedup_key`.

### 8.2 Serialization / expiry
- `Envelope::to_vec()` / `Envelope::from_slice(&[u8])` (`src/lib.rs:229,234`) — JSON bytes for any transport (UDP datagram, HTTP body).
- `Envelope::is_expired(now)` (`src/lib.rs:206`): true when `age = now - created_at ≥ ttl_secs` (and age ≥ 0). Per-type TTL is a **convention set by the emitter**, not enforced by the crate; typical values from the spec: observables `604800`s (7d), alerts `2592000`s (30d), health `120`s (short — absence of a fresh health message is itself the "gone dark" signal). Builder default is `86_400`s (1d).

## 9. How it's wired in the ecosystem (cross-reference)

The crate is transport- and policy-agnostic; the actual sign/verify wiring lives
in the agent and Nexus.

**Agent side** (`/nebulasentinel/nebula-agent/src/gossip/mod.rs`):
- Holds an `Arc<nebula_gossip::signing::Keypair>` (`:61`). On startup it
  **loads-or-creates a persistent key** (`load_or_create_keypair`, `:86`): reads
  32 secret bytes from disk via `Keypair::from_secret_bytes(&b, agent_id)`
  (`:93`), else `Keypair::generate(agent_id)` (`:97`) and persists it. The
  `key_id` is the agent ID.
- Signs every outgoing envelope in place with `nebula_gossip::signing::sign`
  (`:342`, `:480`) before sending.
- Exposes `public_key_hex()` (`:208`) = `hex::encode(keypair.public_bytes())`,
  and **registers that hex public key with the Nexus** at registration time
  (`main.rs:405`, `client.register(..., Some(gossip_engine.public_key_hex()))`).

**Nexus side** (`/nebulasentinel/nexus-server/src/api/mod.rs`):
- On agent registration, stores the hex pubkey in the `agent_gossip_keys` table
  keyed by `agent_id` (`:88`).
- `ingest_gossip_envelope` (`:5478`) parses the body with `Envelope::from_slice`,
  gates on `env.schema == nebula_gossip::SCHEMA`, then **verifies the origin
  signature against the registered key**: looks up `pubkey_hex` for
  `env.origin.id`, hex-decodes to `[u8;32]`, and calls
  `nebula_gossip::signing::verify(&env, &pk)` (`:5512`). Result is stored as
  `sig_ok` (1/0).
- Unknown-key or bad-signature envelopes are still stored (for visibility) but
  flagged `sig_ok=0` and logged — **unless** `gossip_require_signed` is set
  (`main.rs:111`, default `false`, `main.rs:164`), in which case unverified
  envelopes are rejected outright.
- Duplicates are merged by `dedup_key` (UPSERT): a *new* origin bumps the
  corroboration count and appends to `origins_seen`; the *same* origin just
  refreshes `last_seen`/expiry/`confidence` (a re-affirmation, not new evidence).

> **Encoding mismatch to be aware of:** the crate offers `public_b64()`, but the
> agent registers and the Nexus decodes the public key as **hex**
> (`public_key_hex` ↔ `hex::decode`). Both sides use hex consistently, so it
> works — just note `public_b64()` is not the encoding used on this path.

## 10. Security properties

- **Origin authenticity / integrity:** ed25519 signature over canonical bytes
  proves who originated a message and that no signed field was altered. Nexus
  verifies against a **registered-key registry** (`agent_gossip_keys`), so an
  attacker can't forge an envelope for a known agent without its secret key.
- **Relay-hop attestation:** each relayer can sign its hop bound to `msg_id`, so
  a receiver can trace the path and reject forged/untrusted hops
  (`verify_relay`), independent of the origin signature.
- **Signature stability across relays:** relays and `sig` are excluded from
  canonical bytes, so forwarding never invalidates the origin signature — trust
  survives multi-hop epidemic spread.
- **Corroboration:** independent-source counting makes single-source injection
  visible (low corroboration) and cross-source agreement trust-building.
- **Idempotency:** stable `dedup_key`s prevent duplicate-flooding from inflating
  apparent evidence — the same fact reported 50× is one record.
- **Key rotation:** `Signature.key_id` names the signing key, enabling rotation
  without ambiguity.
- **Forward compatibility as a safety property:** unknown `Component` /
  `MsgType` values are preserved verbatim, so a malformed/newer field can't crash
  an older parser (no panic-on-unknown).

## 11. Limitations & caveats

- **Not a formal canonicalization.** Signing relies on serde_json struct field
  ordering and re-serialization of the nested `payload` `Value`; it is not JCS.
  Cross-language signers/verifiers must reproduce this exact byte layout. Producer
  and consumer both go through `canonical_bytes`, so intra-ecosystem it is
  self-consistent.
- **No key management / trust store in-crate.** The crate signs and verifies
  against raw `[u8;32]` public keys handed in by the caller. Distribution,
  rotation, revocation, and the registry all live outside (agent registration +
  Nexus `agent_gossip_keys`).
- **TTL is advisory.** `is_expired` computes expiry but nothing in the crate
  purges expired messages; emitters choose TTLs and consumers must honor them.
- **`confidence` is clamped but `severity`/`disposition`/`ioc_type`/actions are
  free strings** (not validated enums in the typed payloads) — receivers must
  tolerate unexpected values.
- **Typed payloads are a subset of the spec.** See §7.2 divergence note; richer
  spec fields must ride as untyped JSON via `payload_json`.
- **`msg_id` is not a literal ULID/UUIDv7** despite the spec (§3.1) — it is
  `millis_hex-UUIDv4`. Time-sortability is approximate (millis prefix), and the
  hex prefix is fixed-width 11 digits which will need widening beyond the year
  ~5138 (cosmetic).
- **Relay signatures are optional and unenforced.** `add_relay` produces unsigned
  hops; nothing forces relayers to sign, and the crate does not itself walk/verify
  the relay chain — that policy is left to consumers.
- **Single schema version.** `SCHEMA = "gossip/1"`; there is no negotiation or
  migration logic in-crate beyond the Nexus's exact-match gate.
